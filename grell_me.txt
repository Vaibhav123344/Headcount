# BEV Tracker — Layout-Aware Global ID Matching

## Background

The current global matcher assigns the same global ID to **different people** who are far apart because `_cross_camera_dedup` only checks visual similarity (cosine > 0.55) with no spatial gating. Both cameras (Canteen1, Canteen_2) cover the **same area** with heavy overlap. The fix: use **spatial proximity on the BEV layout** as the primary matching signal, with ReID as a secondary tiebreaker.

Additionally, 90% of track updates carry zero-vector embeddings (position-only), which flood the ReID pipeline unnecessarily. The architecture will be split into fast and slow paths.

## User Review Required

> [!IMPORTANT]
> **Layout Calibration Required**: Before this system can work, you must run `layout_calibrator.py` to chain your camera homographies → layout coordinates. This is a manual step where you click 4+ matching floor points. The plan includes instructions.

> [!WARNING]
> **Zone Definitions**: The plan proposes defining zones (e.g., "Counter", "Table Area") as simple rectangles in `config.json`. You'll need to eyeball the pixel coordinates on `map.png` to define them. Alternative: a visual zone-drawing tool. Let me know which you prefer.

### Phase 2: Split Data Flow Architecture

#### [MODIFY] [sct_worker.py](file:///home/yc12214/vaibhav/Headcount/workers/sct_worker.py)

**Change**: Push to TWO queues instead of one:

- **Fast Path** → `warehouse:queue:matcher` — Position-only updates (every frame). Payload: `{cam_id, local_track_id, timestamp, world_x, world_y, velocity_x, velocity_y}`. No image, no embedding. The global matcher uses these for **spatial BEV matching** immediately.

- **Slow Path** → `warehouse:queue:reid` — Image crops for **new/unmatched tracks only**. The SCT worker checks `global_id_map` in Redis: if the local track already has a global ID mapping, it skips the ReID path. Only sends images for tracks that haven't been globally matched yet.

Key changes:
```python
# Every frame: push position-only to matcher (fast path)
self.r.rpush("warehouse:queue:matcher", msgpack.packb(position_payload))

# Only for new tracks without a global ID: push image to ReID (slow path)
if self.get_global_id(local_id) is None and needs_reid:
    reid_payload = {**position_payload, "image_bytes": img_encoded.tobytes()}
    self.r.rpush("warehouse:queue:reid", msgpack.packb(reid_payload))
```

**Change**: Now only receives items that genuinely need ReID enrichment. Extracts embedding, pushes enriched payload to a dedicated queue:

### Phase 3: BEV-Primary Global Matcher

#### [MODIFY] [global_matcher.py](file:///home/yc12214/vaibhav/Headcount/workers/global_matcher.py)

**Major rewrite of matching logic** (keeping the Bayesian framework):

1. **Primary Data Source**: `warehouse:queue:matcher` (position-only, high frequency)
2. **Secondary Data Source**: `warehouse:queue:reid_result` (embeddings, low frequency, async)

**New `process_window()` flow**:

```
For each item in time window:
  1. Project (world_x, world_y) — these are now LAYOUT PIXEL coordinates
  2. If track is already known (in _cam_local_to_global):
     → Update position, velocity (spatial tracking)
  3. If track is NEW/UNMATCHED:
     a. Find all gallery entries from OTHER cameras within 2m spatial radius on BEV
     b. If exactly 1 candidate → MATCH (spatial proximity is unambiguous)
     c. If multiple candidates → Use ReID similarity as tiebreaker (if embedding available)
     d. If 0 candidates → Create new global ID
```

**Updated `_cross_camera_dedup()`**:
```
Before merging, REQUIRE:
  1. Different camera histories (existing check)
  2. BEV spatial distance < 2.0 meters (NEW — prevents merging distant people)
  3. Visual similarity > 0.55 (existing check, now secondary)
```

**Spatial distance calculation** on BEV layout:
- Since world coordinates are now layout pixels, we need a `pixels_per_meter` config value
- `distance_meters = euclidean_distance_pixels / pixels_per_meter`
